# EOD application audit — top-level read

## URGENT

1. **Photos are not scoped to a store or work date.** IndexedDB stores all four photo arrays in one fixed `allPhotos` record, and the daily rollover deliberately preserves it while clearing store/date/shift (`EOD/index.html:5223-5270`, `EOD/index.html:5753-5775`). A user can begin a new store/day with prior cart, signoff, or InstaWork images still loaded, then email or upload them against the newly selected visit (`EOD/index.html:9127-9310`, `EOD/index.html:12930-13300`). This is the highest-risk defect because it can silently attach evidence from the wrong store.

2. **A store-switch race can send EOD links to the wrong Fred Meyer recipients.** `loadStoreData` marks the requested store current before its fetch completes and never checks it again; an older response can overwrite the pools for the currently visible store (`EOD/index.html:5395-5409`). Those pools directly populate `emailRecipients`, which are posted to `/send-eod` (`EOD/index.html:5416-5450`, `EOD/index.html:9167-9417`).

3. **Legacy timesheet printing can fax the wrong store.** The acknowledgement store is filled only when blank, print resolution prefers it over the primary form store, and `/api/eod/print-timesheet` requires authentication but not the store/date confirmation token (`EOD/index.html:6071-6082`, `EOD/index.html:6171-6180`, `eod-api/src/routes/eod-print-timesheet.js:90-122`). A store change after acknowledgement can retain the earlier fax destination.

4. **Several UI role gates are not enforced on the mutation endpoint.** `/sas-upload` can enqueue a supplied store/date/visit image without `requireRole` or day confirmation (`EOD/index.html:3691-3741`, `eod-api/src/sas-bridge.js:681-718`). PROD comment append and signoff-photo POST likewise lack route role/day binding (`eod-api/src/shift-management.js:530-615`, `eod-api/src/sas-bridge.js:1184-1226`). Timesheet edits/delivery, department-signature changes, and digital marks require day confirmation but no lead/supervisor/admin role (`eod-api/src/routes/eod-timesheet-mgmt.js:79-305`, `eod-api/src/routes/dept-signatures.js:62-93`, `eod-api/src/routes/digital-signoffs.js:85-112`). Hidden Rebotics bulk-backlog code suggests admin/district scope, but its backend mutation requires only authentication (`EOD/index.html:3608-3669`, `eod-api/src/rebotics-bridge.js:632-708`).

5. **Stored signoff-photo bytes are publicly retrievable by numeric ID.** The global auth bypass explicitly whitelists `/api/signoff-photos/:photoId/image`, and the route checks no signed token or ownership before returning image data (`eod-api/src/index.js:503-505`, `eod-api/src/sas-bridge.js:1256-1279`).

6. **The app reports SAS photo/coversheet work as synced when it is only queued.** The frontend treats a successful `/sas-upload` enqueue response as completion and never polls the existing job-status endpoint (`EOD/index.html:13265-13300`, `EOD/index.html:13310-13339`; `eod-api/src/sas-bridge.js:721-738`). The worker also claims pending jobs non-atomically, so concurrent service workers can process the same upload twice (`eod-api/src/sas-bridge.js:555-586`).

7. **Two module bridges silently lose recipient/report state.** The monolith copies lexical arrays to `window` instead of exposing accessors (`EOD/index.html:5346`, `EOD/index.html:10560-10572`). Draft hydration later replaces the lexical recipient array, while department signatures mutate the stale `window.emailRecipients` array (`EOD/index.html:5791-5794`, `EOD/eod-dept-signatures.js:263-287`). The help-desk module similarly replaces `window.helpdeskSubmittedReports`, then `syncEodWizardGlobals` immediately overwrites it with the stale lexical array (`EOD/eod-helpdesk-wizard.js:613-614`, `EOD/eod-helpdesk-wizard.js:632-634`, `EOD/index.html:10560-10565`).

## Honest read

The app is feature-complete enough to support the announced field workflow. Store/date selection, day confirmation, profile persistence, multi-shift selection, member management, photo capture/editing, digital worksheet marks, department signatures, timesheet management, materials, preview, and send all have concrete frontend-to-backend paths rather than placeholder function names (`EOD/index.html:4904-5170`, `EOD/index.html:6553-8669`, `EOD/index.html:11179-12384`; `EOD/eod-timesheet-mgmt.js:339-656`; `EOD/eod-digital-signoff.js:211-366`; `EOD/eod-dept-signatures.js:230-590`; `EOD/eod-materials-browser.js:122-868`).

The strongest engineering is at the newer service boundaries. Timesheet management has distinct roster, row, PIN, tablet, JOIN, PDF, fax, office, and supervisor endpoints with day-confirm middleware (`eod-api/src/routes/eod-timesheet-mgmt.js:31-305`). Digital signoff and department signatures separate route logic from persistence libraries (`eod-api/src/routes/digital-signoffs.js:28-143`, `eod-api/src/lib/digital-signoffs.js:82-450`; `eod-api/src/routes/dept-signatures.js:21-93`, `eod-api/src/lib/dept-signatures.js:58-302`). Main shift selection also exact-filters SAS store results instead of trusting substring-prone server filtering (`EOD/index.html:11204-11220`).

The weakest engineering is shared state ownership. One 9,000-line page scope owns form state, four local photo arrays, imported PROD photos, assignments, email pools, shifts, members, sets, help-desk outcomes, review flags, timers, and update state (`EOD/index.html:4415-13686`). Separately loaded modules then read and mutate that state through `window` exports (`EOD/index.html:10526-10572`, `EOD/eod-digital-signoff.js:238-257`, `EOD/eod-dept-signatures.js:263-287`). This makes apparently local changes—store selection, reset, photo import, or set labels—capable of changing email, PDF, SAS, and signoff behavior.

## Single biggest structural risk

The biggest structural risk is **there is no store/date-keyed work session model**. The form is one `kompassEOD` blob; photos are a second, device-wide `allPhotos` blob; signature/profile/day-confirm are separate keys; live shift/set/signature modules keep additional memory/DB state (`EOD/index.html:5223-5343`, `EOD/index.html:5670-5952`, `EOD/index.html:7197-7379`; `EOD/eod-dept-signatures.js:230-258`, `EOD/eod-digital-signoff.js:211-258`). Reset and update paths coordinate these stores through fire-and-forget calls rather than a committed session transaction (`EOD/index.html:5736-5739`, `EOD/index.html:10027-10054`, `EOD/index.html:10173-10271`, `EOD/index.html:13610-13621`).

That structural gap explains the most serious defects: cross-day photos, stale per-store recipient pools, stale timesheet acknowledgement stores, non-persisted InstaWork save status, and timers that survive a shift/reset transition (`EOD/index.html:5753-5775`, `EOD/index.html:5395-5409`, `EOD/index.html:6071-6082`, `EOD/index.html:5183-5191`, `EOD/index.html:12334-12372`).

The same informal boundary causes concrete module drift: materials fallback chooses the first SAS substring-matched visit without exact-store filtering (`EOD/eod-materials-browser.js:613-628`), unsigned department handoff computes a remembered contact with an always-false predicate and then ignores it (`EOD/eod-dept-signatures.js:202-210`), and JOIN expiry calculates two candidates but always returns a different `workDate noon UTC + 30 hours` value (`eod-api/src/lib/timesheet-join.js:73-100`).

## What to fix first

Make the first incremental change a **store/date session guard around photos and outbound actions**, not a rewrite and not a training habit. Stamp store/work date on each photo at capture (exclude mismatches/unstamped from outbound), then key photo storage by the day-confirm token’s store/date so rollover switches sessions instead of preserving a shared bucket (`EOD/index.html:5753-5775`). Surface unsent prior sessions; never auto-delete them. Reject EOD email, InstaWork save, signoff-photo write, SAS upload, and timesheet print when payload store/date do not equal the active day-confirm token (`EOD/index.html:4916-4956`, `EOD/index.html:5223-5270`, `EOD/index.html:9413-9417`, `EOD/index.html:9482-9517`, `EOD/index.html:12907-12919`, `EOD/index.html:13265-13323`, `EOD/index.html:6440-6451`).

In the same production-safety tranche, add route roles and exact visit/store/date assertions to SAS mutations, protect signoff image retrieval with a signed/opaque authorization mechanism, discard stale store-data responses, exact-filter the materials fallback, bind timesheet printing to day confirmation, and make upload completion reflect worker completion rather than enqueue acceptance (`eod-api/src/sas-bridge.js:681-718`, `eod-api/src/shift-management.js:530-615`, `eod-api/src/sas-bridge.js:1256-1279`, `EOD/index.html:5395-5409`, `EOD/eod-materials-browser.js:613-628`, `eod-api/src/routes/eod-print-timesheet.js:90-122`, `eod-api/src/sas-bridge.js:721-738`). These are narrow controls around existing workflows; none requires replacing the monolith.

## Bottom line

The app is not a collection of stubs. Its core workflows are implemented, and the newer modules have usable boundaries (`EOD/eod-timesheet-mgmt.js:1-700`, `EOD/eod-dept-signatures.js:1-619`, `EOD/eod-digital-signoff.js:1-393`, `EOD/eod-materials-browser.js:1-902`). It is fragile where identity, store/date context, and mutable browser state cross those boundaries. Production announcement should not imply that every send/upload is context-safe until the urgent findings above are addressed.
